## 프로젝트 개요

### 1.1 목표

- RV32I 5-stage 파이프라인 CPU를 Ultra96 v1 FPGA에 포팅
- BRAM을 이용한 Instruction Memory (IMEM) / Data Memory (DMEM) 구현
- Processing System (PS)에서 AXI BRAM Controller를 통해 메모리 접근 가능하도록 구성
- **최종 목표**: CPU + BRAM을 PL(Programmable Logic)에 구현, PS에서 프로그램 로드 및 실행 가능

### 1.2 하드웨어 사양

| 항목 | 사양 |
|------|------|
| **FPGA 보드** | Ultra96 v1 (Zynq-7000 MPSoC) |
| **메모리 종류** | Dual-Port BRAM (Port A: PS/AXI 접근, Port B: CPU 접근) |
| **IMEM 크기** | 16384 words (64KB) |
| **DMEM 크기** | 16384 words (64KB) |
| **CPU 아키텍처** | RV32I (6-stage 파이프라인, MEM2 포함) |
| **초기 클럭** | 50 MHz |

## 핵심 기술 문제

### 2.1 문제: BRAM의 동기식 읽기 지연

#### 비동기식 RAM vs 동기식 BRAM

**비동기식 RAM (기존 설계)**:
```
주소 설정 → 즉시 데이터 출력 (조합 논리)
```

**동기식 BRAM (실제 FPGA)**:
```
Cycle N:   BRAM 주소 입력
Cycle N+1: BRAM 데이터 출력 (1-cycle 지연)
```

#### 기존 파이프라인의 문제

5-stage 파이프라인:
```
IF(명령 페칭) → ID(해석) → EX(실행) → MEM(메모리) → WB(쓰기)
```

**문제 케이스**:
```
Cycle N:   MEM 단계에서 LW x2, 0(x1) 실행
           → BRAM에 주소 저장, enable 신호 활성화
           → 이 사이클에 데이터 안 나옴 (동기식!)

Cycle N+1: MEM 단계 끝남
           → 메모리 데이터 아직 유효 안 함
           → WB에서 레지스터에 쓰기 못 함 (garbage 쓰기)
```

**결과**: 로드 명령이 정상 작동하지 않음

### 2.2 세부 분석

#### Load-Use Hazard 발생

```c
// C 코드
lw x2, 0(x1)   // x2에 메모리에서 로드
add x3, x2, x4 // 로드된 x2를 즉시 사용
```

**파이프라인 진행**:

| Cycle | IF | ID | EX | MEM | WB |
|-------|----|----|----|----|-----|
| 1 | LW | | | | |
| 2 | ADD | LW | | | |
| 3 | | ADD | LW | | |
| 4 | | | ADD | LW | |
| 5 | | | | ADD | LW |
| 6 | | | | | ADD |

문제:
- **Cycle 4**: ADD가 EX에 진입하려면 x2 값 필요
- **Cycle 4**: 하지만 LW의 x2 쓰기는 Cycle 5의 WB에서 일어남
- **Cycle 4**: x2 데이터 아직 준비 안 됨 → 에러!

## 해결 방안

### 3.1 핵심 아이디어: MEM2 파이프라인 단계 추가

#### 새로운 파이프라인 구조

**변경 전 (5-stage)**:
```
IF → ID → EX → MEM → WB
```

**변경 후 (6-stage, MEM2 추가)**:
```
IF → ID → EX → MEM → MEM2 → WB
```

#### 각 단계의 역할

| 단계 | 역할 | 메모리 | 데이터 |
|------|------|--------|--------|
| **IF** | 명령 페칭 | 주소 전송 | - |
| **ID** | 명령 해석 | - | - |
| **EX** | 연산 실행 | - | ALU 결과 |
| **MEM** | BRAM 접근 | 주소 설정, 데이터 송수신 신호 | (아직 read 진행중) |
| **MEM2** | BRAM read 대기 | - | **BRAM에서 데이터 수신** ✓ |
| **WB** | 레지스터 쓰기 | - | 데이터를 RF에 쓰기 |

**타이밍 예시**:
```
Cycle N:   LW x2, 0(x1) MEM 진입
           BRAM Port B에 주소 설정, enable=1

Cycle N+1: LW x2, 0(x1) MEM2 진입
           BRAM에서 데이터 출력됨 ✓
           → MEM2 단계에서 MemRData2RF로 정렬/확장

Cycle N+2: LW x2, 0(x1) WB 진입
           x2 ← MEMWB_MemRData2RF
           ✓ 정상 쓰기 완료

Cycle N+2: ADD x3, x2, x4 EX 진입
           하지만 x2 아직 WB 안 끝남
           → Forwarding으로 MemRData2RF 직접 사용
```

### 3.2 Load-Use Hazard 처리: 2-Cycle Stall

동기식 BRAM이므로 load 후 **2 cycles 기다려야** 데이터 유효:

```
Cycle N:     LW x2, 0(x1)   ID→EX 진입
             load_use_hazard = 1
             → Stall!
             
Cycle N+1:   LW x2, 0(x1)   EX→MEM 진입
             load_use_hold = 1 (이전 stall 기억)
             ADD x3, x2, x4 ID 진입
             → stall = load_use_hold = 1
             → ADD Stall!
             
Cycle N+2:   LW x2, 0(x1)   MEM→MEM2 진입
             x2 데이터 MEM2에서 준비됨 ✓
             ADD x3, x2, x4 EX 진입
             → Forwarding으로 x2 데이터 받기 ✓
```

### 3.3 Forwarding 우선순위

메모리 동기식 처리로 인해 Forwarding 경로 추가:

```
우선순위:
1. MEM2 (최우선)  → 동기 BRAM에서 로드된 데이터 (가장 최신)
2. MEM            → 산술 연산 결과만 (로드 제외)
3. WB             → 일반 쓰기 결과
4. RF (없음)      → 레지스터 파일에서 읽기
```


##### 변경 5: Forwarding 로직 확장 (약 560-700줄)

**변경 전** (MEM까지만 지원):
```verilog
wire [31:0] exmem_fwd_data;
assign exmem_fwd_data = (EXMEM_jal | EXMEM_jalr) ? EXMEM_pc_plus4 :
                        EXMEM_aluout;  // Load data is available in MEM2 stage
```

**변경 후** (MEM2까지 확장, 로드 데이터 우선):
```verilog
// MEM2 포워딩 데이터 생성
wire [31:0] mem2_fwd_data;
assign mem2_fwd_data = (MEM2_jal | MEM2_jalr) ? MEM2_pc_plus4 :
                       (MEM2_MemtoReg) ? MemRData2RF :  // 로드 데이터
                       MEM2_aluout;

// MEM 포워딩 선택은 forwardA/forwardB에서 MemtoReg를 제외시킴

// Forwarding 선택: 2-bit (00: RF, 01: WB, 10: MEM, 11: MEM2)
assign forwardA = ((MEM2_RegWrite) && (MEM2_rd != 5'b0) && 
                   (MEM2_rd == rs1)) ? 2'b11 :      // MEM2 우선
                  ((EXMEM_RegWrite) && ~EXMEM_MemtoReg && ...) ? 2'b10 :
                  ((MEMWB_RegWrite) && ...) ? 2'b01 :
                  2'b00;

// Forwarding Mux
always @(*)
begin
  case (forwardA)
    2'b00: forward_rs1_data = IDEX_rs1_data;
    2'b01: forward_rs1_data = rd_data;          // WB 단계
    2'b10: forward_rs1_data = exmem_fwd_data;   // MEM 단계
    2'b11: forward_rs1_data = mem2_fwd_data;    // MEM2 단계 (로드 데이터)
    default: forward_rs1_data = IDEX_rs1_data;
  endcase
end
```

**중요**: MEM2에서만 **로드 데이터** forward!
- MEM에서는 로드 명령의 BRAM 읽기가 진행 중이므로 아직 유효하지 않음
- MEM2에서 동기식 read 완료 후 포워딩 가능

##### 변경 6: Load-Use Hazard 스톨 로직 강화 (약 680-750줄)

**변경 전** (1-cycle stall):
```verilog
// Load 명령이 EX에 있고, rs1/rs2가 로드 대상이면 stall
assign stall = (IDEX_MemtoReg && 
                ((IDEX_rd == rs1) || ((is_S_type || is_R_type) && (IDEX_rd == rs2))) && 
                (IDEX_rd != 5'b0));
```

**변경 후** (2-cycle stall):
```verilog
// 동기식 BRAM: 2-cycle 스톨 필요
reg [1:0] load_use_hold;  // 2-cycle hold 카운터

always @(posedge clk)
begin
  if (reset)
    load_use_hold <= 2'b00;
  else if (load_use_hazard)
    load_use_hold <= 2'b01;
  else if (load_use_hold != 2'b00)
    load_use_hold <= load_use_hold - 1'b1;
end

// 현재 또는 hold 카운터가 남아있으면 stall
assign stall = load_use_hazard | (load_use_hold != 2'b00);

// load_use_hazard 정의 (load 명령 감지)
assign load_use_hazard = (IDEX_MemtoReg && 
                          ((IDEX_rd == rs1) || 
                           ((is_S_type || is_R_type) && (IDEX_rd == rs2))) && 
                          (IDEX_rd != 5'b0));
```

**타이밍 분석**:
```
Cycle N:   load_use_hazard=1, load_use_hold=0
           stall = 1 | 0 = 1 → 파이프라인 정지

Cycle N+1: load_use_hazard=0 (명령 진행), load_use_hold=1
           stall = 0 | 1 = 1 → 계속 정지 (2-cycle stall 완성!)

Cycle N+2: load_use_hazard=0, load_use_hold=0
           stall = 0 → 재개, Forwarding으로 데이터 사용
```

### 4.3 시스템 통합: 외부 BRAM 포트 노출

#### 4.3.1 파일: `FPGA/Pipeline/260511_Pipeline/rtl/RV32I_System.v`

이 파일은 CPU와 메모리를 통합하고 외부 BRAM 포트를 노출합니다.

**변경 전** (내부 메모리 통합):
```verilog
module RV32I_System #(
  parameter [31:0] CPU_RESET_PC = 32'h1000_0000
)(
  input  CLOCK_50,
  input  reset
);
  // CPU 내부에 inst_memory, data_memory 포함
  
  rv32i_cpu #(.RESET_PC(CPU_RESET_PC)) icpu (
    .clk(CLOCK_50),
    .reset(~reset),
    .pc(fetch_addr),
    .inst(inst_internal),  // 내부 메모리에서만 읽음
    ...
  );
  
  inst_memory iIMem (.address(fetch_addr), .instruction(inst_internal));
  data_memory iDMem (.address(data_addr), .read_data(read_data_internal));
endmodule
```

**변경 후** (외부 BRAM 포트 노출):
```verilog
module RV32I_System #(
  parameter [31:0] CPU_RESET_PC = 32'h1000_0000
)(
  input         CLOCK_50,
  input         reset,

  // ===== Instruction Memory BRAM Port B (CPU에서 읽기) =====
  output [31:0] imem_addr,       // BRAM 주소 버스
  input  [31:0] imem_rdata,      // BRAM에서 데이터 읽기
  output        imem_en,         // BRAM enable 신호

  // ===== Data Memory BRAM Port B (CPU 읽기/쓰기) =====
  output [31:0] dmem_addr,       // BRAM 주소 버스
  output [31:0] dmem_wdata,      // BRAM에 데이터 쓰기
  input  [31:0] dmem_rdata,      // BRAM에서 데이터 읽기
  output [3:0]  dmem_we,         // Byte Enable (비트별 쓰기)
  output        dmem_en          // BRAM enable 신호
);

  // CPU 코어 인스턴스
  rv32i_cpu #(.RESET_PC(CPU_RESET_PC)) icpu (
    .clk(CLOCK_50),
    .reset(~reset),
    .pc(fetch_addr),
    .inst(inst),           // 외부 BRAM에서 제공
    .MemWrite(data_we),
    .MemAddr(data_addr),
    .MemWData(write_data),
    .ByteEnable(ByteEnable),
    .MemRData(read_data)   // 외부 BRAM에서 제공
  );

  // ===== BRAM 포트 매핑 =====
  // IMEM 포트
  assign imem_addr  = fetch_addr;
  assign inst       = imem_rdata;
  assign imem_en    = 1'b1;        // 항상 enable (async read 방지)

  // DMEM 포트
  assign dmem_addr  = data_addr;
  assign dmem_wdata = write_data;
  assign read_data  = dmem_rdata;
  assign dmem_en    = 1'b1;

  // ⚠️ 중요: write enable 신호 게이팅
  // 로드 명령(data_we=0)일 때 BRAM에 쓰기 방지
  assign dmem_we = data_we ? ByteEnable : 4'b0000;
endmodule
```

**포트별 설명**:

| 포트 | 방향 | 설명 |
|------|------|------|
| `imem_addr[31:0]` | OUT | Instruction Memory 주소 |
| `imem_rdata[31:0]` | IN | Instruction Memory 읽기 데이터 |
| `imem_en` | OUT | Instruction Memory Enable |
| `dmem_addr[31:0]` | OUT | Data Memory 주소 |
| `dmem_wdata[31:0]` | OUT | Data Memory 쓰기 데이터 |
| `dmem_rdata[31:0]` | IN | Data Memory 읽기 데이터 |
| `dmem_we[3:0]` | OUT | Data Memory Byte Write Enable |
| `dmem_en` | OUT | Data Memory Enable |

## 설계 결정사항

### 6.1 왜 MEM2 파이프라인 단계를 추가했는가?

**문제**:
- BRAM 읽기는 1-cycle 지연
- 기존 5-stage 파이프라인은 MEM 단계에서 즉시 데이터 사용 가정

**해결**:
- MEM 단계: BRAM에 주소/제어 신호 설정 (읽기 진행)
- MEM2 단계: BRAM에서 출력된 데이터 수신 (1-cycle 후)
- WB 단계: 데이터를 레지스터에 쓰기

**장점**:
- 파이프라인 구조 일관성 유지
- 모든 명령(로드/비로드)이 동일한 단계 진행
- 타이밍 분석 단순화

---

### 6.2 왜 2-Cycle Load-Use Stall인가?

**분석**:

```
Cycle N:   LW x2, 0(x1)
           ID/EX 단계, IDEX_MemtoReg=1
           → load_use_hazard=1
           → stall=1, ID 이전 단계 정지

Cycle N+1: LW x2, 0(x1)
           EX/MEM 단계 진입, IMEM 동기식이므로 BRAM read 진행
           → load_use_hazard=0
           → load_use_hold=1 (이전 stall 기억)
           → stall=1, 계속 정지

Cycle N+2: LW x2, 0(x1)
           MEM/MEM2 단계 진입, x2 데이터 MEM2에서 수신 ✓
           ADD x3, x2, x4 진입 EX 단계
           → stall=0, 재개
           → Forwarding으로 x2 데이터 직접 사용
```

**결과**: 2-cycle 정확한 처리

---

### 6.3 Forwarding 우선순위 설정

| 순위 | 출처 | 데이터 | 이유 |
|------|------|--------|------|
| 1️⃣ | **MEM2** | 로드 데이터 | 가장 최신, 동기 BRAM 완료됨 |
| 2️⃣ | **MEM** | 산술 결과만 | 로드 제외 (메모리 읽기 진행중) |
| 3️⃣ | **WB** | 일반 쓰기 | 구형 데이터 |
| 4️⃣ | **RF** | 레지스터 | 최악의 경우 |

**이유**: MEM 단계의 로드 명령은 아직 메모리 읽기가 진행 중이므로, 데이터가 유효하지 않음. MEM2에 도달해야만 유효.

---

### 6.4 내부 메모리 vs 외부 BRAM 포트

**선택**: 외부 BRAM 포트 노출 (RV32I_System에 BRAM 포트)

**이유**:
1. **재사용성**: 다른 BRAM 인터페이스(AXI, APB 등)와 쉽게 교환 가능
2. **검증 용이**: 시뮬레이션에서 메모리 초기화, 모니터링 용이
3. **FPGA 구현**: PS/AXI와 BRAM 직접 연결 가능
4. **스케일링**: 멀티 포트 BRAM 지원 확장 용이


#### 7.1.2 주요 구성 요소

1. **AXI BRAM Controller** (2개, IMEM/DMEM용)
   - 역할: AXI 프로토콜 ↔ BRAM 인터페이스 변환
   - Port A: PS의 AXI 마스터 연결
   - Port B: PL의 CPU 모듈 연결

2. **BRAM** (2개, 각 64KB)
   - IMEM: Instruction Memory (읽기 전용, CPU 관점)
   - DMEM: Data Memory (읽기/쓰기)
   - 동기식 포트 B 지원

3. **CPU Module** (PL에 구현)
   - RV32I 파이프라인 (6-stage)
   - 외부 IMEM/DMEM 포트와 연결

---

#### 7.1.3 주소 맵 (예상)

| 메모리 | 시작 주소 | 크기 | 포트 | 용도 |
|--------|----------|------|------|------|
| IMEM | 0x4000_0000 | 64KB | Port A (AXI) / Port B (CPU) | 프로그램 코드 |
| DMEM | 0x4001_0000 | 64KB | Port A (AXI) / Port B (CPU) | 데이터 |

**PS 관점**:
- AXI Master에서 0x4000_0000-0x4001_FFFF 주소 범위로 읽기/쓰기
- AXI BRAM Controller가 BRAM 접근으로 변환

**CPU 관점** (PL):
- 내부 주소: 0x1000_0000 (IMEM), 0x2000_0000 (DMEM)
- BRAM Port B는 이 주소를 word address [15:2]로 변환

### 7.2 클럭 튜닝

#### 7.2.1 초기 설정

- **시작 주파수**: 50 MHz (안정성 우선)
- **목표 주파수**: 100 MHz 이상 (타이밍 분석 후)

#### 7.2.2 타이밍 분석 방법

1. Vivado Implementation 실행
2. Timing Summary 확인
3. **WNS (Worst Negative Slack)** 확인
   - WNS > 0: 타이밍 만족, 클럭 상향 가능
   - WNS < 0: 타이밍 실패, 클럭 하향 필요

#### 7.2.3 성능 예측

**본 설계의 critical path**:
```
BRAM read latency (1-cycle) > Forwarding Mux > Arithmetic
```

대부분의 지연이 **BRAM 접근과 메모리 포워딩**에서 발생하므로, 100 MHz 이상은 어려울 것으로 예상. 보수적으로 50-75 MHz에서 시작 권장.

---

### 7.3 검증 및 테스트

#### 7.3.1 하드웨어 검증 계획

1. **BRAM 쓰기/읽기 검증**
   - PS에서 IMEM/DMEM에 데이터 쓰기
   - CPU에서 데이터 읽기 및 조작
   - 결과를 PS에서 확인

2. **CPU 실행 검증**
   - 간단한 프로그램 (덧셈, 배열 접근) 실행
   - DMEM에 결과 저장
   - PS에서 DMEM 읽어 검증

3. **Hazard 및 Forwarding 검증**
   - Load-use hazard 상황 생성
   - 정확한 2-cycle stall 확인
   - 데이터 정합성 확인

#### 7.3.2 디버깅 도구

- **Vivado Hardware Manager**: JTAG를 통한 실시간 모니터링
- **Logic Analyzer**: 신호 계층 추적
- **ILA (Integrated Logic Analyzer)**: PL의 내부 신호 캡처
